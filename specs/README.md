# `specs/` — Python-orchestrated, Rust-executed AIPerf design record

This folder is the design record for **Python-orchestrated, Rust-executed
AIPerf** on branch `ajc/rust`: Python owns the user CLI, Config v2, outer loops,
and presentation; the sole Rust executable is the one `aiperf` binary (crate
`aiperf-cli`, both front door and execution engine); and the `rust/runtime`
package (crate `aiperf-runtime`) is a runtime library, not a second CLI. The thesis
across every spec is the same: keep AIPerf's *external contracts* and its
*earned-in-blood algorithms* (SSE parsing, timing breakdown, metric formulas,
firing-gate arithmetic), keep the **`{clock}` + `{transport}` trait seam** as the
crown jewel (it is what makes real / mock / offline execution modes free), and
throw away every internal artifact of the Python multiprocess/GIL model (ZMQ bus,
services, credit protocol, `plugins.yaml`, shard export, mmap cache). The specs
are **design intent** — the code in `rust/` is a walking skeleton that is ahead
of and behind them in places. When they disagree, the code wins; verify before
relying on any spec feature (see [`../llms.txt`](../llms.txt) and the four agent
files for the code-vs-spec gaps).

Reading order for a newcomer: the **ledger** first (it frames scope), then the
**north star** (the target shape), then whichever subsystem you are touching.

## Conventions

- **Each spec body reflects the current, final state.** These specs were folded on
  2026-07-13 so every earlier dated addendum is now merged into the body it revised;
  where a later decision superseded an earlier one, the body describes the final
  reality and the superseded text is gone. When a decision, implementation, or removal
  later changes a spec, edit the body in the same change to keep it true, and record
  the standing in the Status column here. Keep the historical narrative singular — a
  spec should describe what *is* (or what was designed and then removed), not a diff log.
- **Status column** reflects the whole spec's current standing: `built` (implemented,
  verify per-claim against `rust/`), `decided` (the design holds), `design` / `sketch`
  (proposed, not built), `partly built` (some code exists), `removed` (was built or
  designed, then deleted from the tree), `superseded` (a newer spec overrides it — the
  row says which).
