# Glossary

Definitions of key terms used in AIPerf documentation.

## A

**Aggregate Metric**
: A metric computed by tracking or accumulating values across all requests in real-time during a benchmark. Examples: request count, total output tokens. See [Metrics Reference](metrics_reference.md#aggregate-metrics).

**Arrival Pattern**
: The distribution of inter-arrival times between requests. Common patterns: constant (uniform spacing), Poisson (realistic bursty), gamma (tunable smoothness). See [Arrival Patterns Tutorial](tutorials/arrival-patterns.md).

**Artifact Directory**
: The output directory where AIPerf saves all benchmark results. Default: `artifacts/`. Configure with `--output-artifact-dir`.

## B

**Benchmark Duration**
: Total elapsed wall-clock time from first request sent to last response received. Formula: `max_response_timestamp - min_request_timestamp`.

**Baseline**
: A reference benchmark run used for comparison. Establish baselines before optimizations or configuration changes.

**Burst Traffic**
: Traffic pattern with high variance in arrival times, simulating sudden spikes in load. Use gamma distribution with low smoothness value.

## C

**Chunk**
: A portion of a streaming response containing one or more tokens. Used to calculate inter-chunk latency.

**Completion Tokens**
: Output tokens generated by the model, excluding reasoning tokens. Also called "output tokens."

**Concurrency**
: Number of simultaneously in-flight requests. AIPerf maintains this level by issuing a new request immediately when one completes.

**Connection Pool**
: A cache of reusable HTTP connections to reduce connection overhead. Default limit: 2,500 connections.

**Credit**
: An internal token representing permission to send a request. TimingManager issues credits according to the timing strategy.

## D

**Dataset**
: Collection of prompts or conversations used for benchmarking. Can be synthetic (generated), custom (from file), or public (e.g., ShareGPT).

**Derived Metric**
: A metric computed by applying formulas to other metric results after they're available. Examples: request throughput, benchmark duration. See [Metrics Reference](metrics_reference.md#derived-metrics).

**DCGM (Data Center GPU Manager)**
: NVIDIA tool for GPU monitoring. AIPerf integrates with DCGM Exporter for GPU telemetry collection.

## E

**Endpoint**
: The API type being benchmarked (chat, completions, embeddings, etc.). Each endpoint has specific request/response formats.

**Export Level**
: Controls which output files are generated: `summary` (aggregate only), `records` (per-request), `raw` (full request/response data).

## F

**Fixed Schedule**
: Timing mode that replays requests at exact timestamps from a trace file. Enables deterministic workload replay.

## G

**Goodput**
: Throughput of requests meeting all user-defined Service Level Objectives (SLOs). Formula: `good_request_count / benchmark_duration`. See [Goodput Tutorial](tutorials/goodput.md).

**Grace Period**
: Time to wait for responses after benchmark duration ends. Responses within grace period are included in metrics.

## H

**HTTP Trace**
: Detailed timing data for HTTP request lifecycle (DNS, TCP, TLS, TTFB, etc.). Follows k6 naming conventions. See [HTTP Trace Metrics Tutorial](tutorials/http-trace-metrics.md).

## I

**ICL (Inter Chunk Latency)**
: Time gaps between consecutive response chunks in a streaming response. Provides distribution of chunk arrival times.

**ISL (Input Sequence Length)**
: Number of tokens in the input prompt. Formula: `len(tokenizer.encode(prompt))`.

**ITL (Inter Token Latency)**
: Average time between consecutive tokens during generation, excluding TTFT. Formula: `(request_latency - TTFT) / (OSL - 1)`. Lower is better for smooth streaming.

## K

**Keepalive**
: Mechanism to maintain persistent HTTP connections. Reduces connection overhead for subsequent requests.

**KV Cache**
: Key-Value cache used by transformers to store attention states. Can be shared across requests with common prefixes.

## L

**Load Balancing**
: Distributing requests across multiple inference servers. AIPerf supports client-side load balancing with `--url` (multiple URLs).

**Load Pattern**
: The strategy for controlling when requests are sent. Includes concurrency, request-rate, and trace replay modes.

## M

**Metric Flag**
: Metadata indicating when/how a metric is computed. Examples: `STREAMING_ONLY`, `PRODUCES_TOKENS_ONLY`, `NO_CONSOLE`.

**Multi-Turn Conversation**
: A benchmark session consisting of multiple request-response exchanges, simulating realistic user interactions.

## N

**Non-Streaming**
: Request mode where the server returns the complete response in a single message, rather than incrementally.

## O

**OSL (Output Sequence Length)**
: Total completion tokens generated (output tokens + reasoning tokens). Formula: `output_token_count + reasoning_token_count`.

**Output Token**
: A non-reasoning token generated by the model as part of the response content.

**Outlier**
: A measurement significantly different from typical values. Usually identified by high percentiles (P99, P99.9).

## P

**P50, P90, P99 (Percentiles)**
: Statistical measures indicating the value below which a percentage of observations fall. P99 = 99th percentile = worst 1% of requests are above this value.

**Payload**
: The JSON request body sent to the inference server, formatted according to endpoint type.

**Percentile**
: A value below which a given percentage of observations fall. Better than averages for understanding tail latencies.

**Plugin**
: An extensible component registered in `plugins.yaml`. Categories: endpoint, transport, dataset, timing strategy, etc. See [Plugin System](plugins/plugin-system.md).

**Poisson Distribution**
: Probability distribution modeling random, independent events at a constant average rate. Used for realistic traffic patterns.

**Prefill**
: The initial phase of inference where the model processes the input prompt before generating tokens.

**Prefill Concurrency**
: Maximum number of requests allowed in prefill phase simultaneously. Prevents OOM with long contexts.

**Prefix Caching**
: Server optimization that reuses KV cache from common prompt prefixes across requests.

**Prompt**
: The input text sent to the model. Measured in tokens (ISL).

## Q

**QPS (Queries Per Second)**
: Synonym for request throughput. Number of requests completed per second.

## R

**Ramp Duration**
: Time period over which concurrency or request rate gradually increases from minimum to target.

**Random Seed**
: Integer value initializing random number generation for reproducible datasets. Use `--random-seed 42` for deterministic prompts.

**Reasoning Token**
: Token used for internal "thinking" or chain-of-thought reasoning, separate from output tokens. Exposed in `reasoning_content` field by some models.

**Record**
: A single request-response pair with all associated metrics and timing data.

**Record Metric**
: A metric computed individually for each request-response pair. Examples: TTFT, ITL, request latency. See [Metrics Reference](metrics_reference.md#record-metrics).

**Record Processor**
: Service that computes metrics from raw request-response data. Multiple processors run in parallel for scalability.

**Records Manager**
: Service that aggregates processed records and generates final results.

**Request Rate**
: Target number of requests to send per second. Timing strategy generates inter-arrival delays to achieve this average rate.

**Request Throughput**
: Completed requests per second across entire benchmark. Formula: `request_count / benchmark_duration`.

## S

**Sequence Distribution**
: Mixed workload specification with ISL/OSL pairs and probabilities. Format: `ISL,OSL:prob;ISL,OSL:prob`. Example: `256,128:50;512,256:50`.

**Service**
: An AIPerf component running in a separate process. Examples: Worker, TimingManager, DatasetManager, RecordProcessor.

**Session**
: A multi-turn conversation between user and model. AIPerf tracks sessions for conversation-based benchmarks.

**SLO (Service Level Objective)**
: A target value for a metric defining acceptable performance. Used in goodput calculation.

**Smoothness**
: Parameter for gamma arrival pattern controlling distribution shape. Higher = more regular, lower = more bursty.

**SSE (Server-Sent Events)**
: HTTP streaming protocol used for incremental response delivery. Required for measuring TTFT and ITL.

**Streaming**
: Response mode where server sends tokens incrementally as they're generated, rather than waiting for completion.

## T

**Telemetry**
: System metrics collected during benchmarking (GPU utilization, memory, temperature, etc.).

**Timeslice**
: Fixed time window for dividing benchmark into segments. Enables analysis of performance trends over time.

**Timing Strategy**
: Algorithm determining when to issue each request. Types: fixed_schedule, request_rate, user_centric_rate.

**Token**
: Smallest unit of text processed by language models. A word is typically 1-3 tokens.

**Tokenizer**
: Tool that converts text to tokens. AIPerf uses HuggingFace tokenizers for client-side token counting.

**Trace**
: A recorded sequence of requests with timestamps, enabling deterministic replay.

**TTFB (Time To First Byte)**
: HTTP metric measuring time from request end to first response byte. Part of HTTP trace metrics.

**TTFO (Time To First Output Token)**
: Time from request start to first non-reasoning output token. Equivalent to GenAI-Perf's TTFT for reasoning models.

**TTFT (Time To First Token)**
: Time from request start to first token (including reasoning tokens). Key metric for interactive responsiveness. Lower is better.

**TTST (Time To Second Token)**
: Time gap between first and second tokens. Helps isolate startup overhead from steady-state generation.

**Throughput**
: Rate of completing work. Types: request throughput (requests/sec), output token throughput (tokens/sec).

## U

**Usage Field**
: API response field containing server-reported token counts. Used to compare with client-side tokenization.

**User-Centric Timing**
: Timing mode where each user has independent rate limiting and blocking behavior. See [User-Centric Timing Tutorial](tutorials/user-centric-timing.md).

## V

**Variance**
: Statistical measure of spread in a distribution. High variance = inconsistent performance.

## W

**Warmup**
: Initial phase of benchmark to eliminate cold-start effects. Warmup requests are excluded from final metrics.

**Worker**
: AIPerf process that sends HTTP requests to the inference server. Multiple workers run in parallel for scalability.

**Worker Manager**
: Service that coordinates worker lifecycle, health monitoring, and load balancing.

## Z

**ZMQ (ZeroMQ)**
: High-performance message library used for internal communication between AIPerf services.
