# Commit 044 — `082a51827e`

## Upstream intent

Upstream adds TraceLab as a first-class recorded-agent trace source. The
released corpus is JSONL (usually gzip-compressed) with one row per LLM round,
not one executable trace per document. The new loader groups rounds by
`session_id`, derives request timing from nested `timing_events`, synthesizes
whole-block cache identities from `input_tokens_total` and `prefix_tokens`, and
converts each root session to the existing WEKA trace schema.

The conversion also recovers one level of subagent topology. Claude `Agent` and
`Task` tool-call windows are precise blocking spawn windows. Codex
`spawn_agent` through `wait_agent` is a coarser session-level window because the
published corpus strips agent handles. Candidate children must share user and
project identity and have their complete recorded span contained by the spawn
window; the tightest matching window wins. Grandchildren and children which
cannot be placed remain standalone traces rather than being discarded.

Upstream also adds plain/gzip source handling, a default 64-token block size
with an authored override, sequential selection, context filtering and entry
caps, format/config/plugin/cache routing, fixed-schedule recognition, explicit
errors for invalid or unreadable input, and documentation.

## Native applicability

The native runtime already has the strict WEKA parser, cache-block content
reconstruction, subagent Graph-IR lowering, graph selection, and replay engine.
It has no TraceLab acquisition or conversion boundary and does not classify
`tracelab` as a graph format. Sending the corpus to the linear loader registry
would lose subagent topology and would choose the wrong execution model.

The native port therefore adds a TraceLab recorded-graph compiler. It acquires
the source once, converts grouped sessions to the existing strict WEKA-shaped
in-memory representation, and immediately invokes the native WEKA Graph-IR
compiler. The final metadata format remains `tracelab`; no converted file is
written. CLI `--input-file ... --custom-dataset-type tracelab` and Config v2
`dataset.format: tracelab` select the graph workload, and `--isl-block-size`
reaches the converter as `options.block_size`.
