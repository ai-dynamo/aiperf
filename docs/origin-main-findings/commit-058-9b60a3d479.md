# Origin #58 closure: FakeTokenizer prompt-special-token count

Upstream commit `9b60a3d479fd808373c077686c0bbe367d431bec` adds one
test-harness method, `FakeTokenizer.num_prompt_special_tokens() -> 0`.  The
method lets Python test doubles satisfy a Python dataset-composition call site;
it does not change production tokenization, request bytes, or an artifact
contract.

## Ancestry and source comparison

The exact upstream object is already an ancestor of the campaign base through
the two-parent merge `e23f5f835e05d1f0e1cc8a403ebfa50096feca5c`; its second
parent is `9b60a3d479fd808373c077686c0bbe367d431bec`. The current semantic tree
had nevertheless regressed: `FakeTokenizer` no longer provided the method.
The focused upstream regression failed with `AttributeError` before this
restoration and passes after restoring the exact zero-returning method.

Native test doubles are Rust implementations of
`aiperf_runtime::dataset::tokenizer::TextTokenizer`; there is no Python
`FakeTokenizer` bridge or factory in a native profile.  The relevant native
contract already provides `num_special_tokens_to_add() -> 0` as a trait
default at `rust/runtime/src/dataset/tokenizer.rs`.  Native Hugging Face
tokenizers override that default from their post-processor, while test-only
tokenizers deliberately inherit zero.  This is the same semantic result for a
bare-input fake without incorrectly adding a Python-shaped public API.

## Disposition and verification

The lost Python harness behavior is applicable and is restored. A duplicate
native fake or manual native zero override remains not applicable: it would
not exercise a product path and would make the trait contract less clear.

- `git merge-base --is-ancestor 9b60a3d479 HEAD`: success.
- `git show e23f5f835e2^2:tests/harness/fake_tokenizer.py` contains the exact
  upstream method; the focused test proved the current tree had lost it, then
  verifies the restored method returns zero.
- `TextTokenizer` defaults `num_special_tokens_to_add` to zero; its
  `NoDecodeTokenizer` test fixture relies on that default.
- Native scope audit: `NoDecodeTokenizer` deliberately inherits the trait
  default, and the existing
  `text_tokenizer_default_batch_is_ordered_and_empty_safe` Rust unit test
  exercises that default test-tokenizer composition boundary.
