# Commit 051 — `324bb05773`

## Upstream intent

Upstream adds the opt-in `--per-chunk-usage` endpoint policy. For streaming chat
requests it requests cumulative usage on every response chunk through
`stream_options.continuous_usage_stats`, in addition to the existing
`stream_options.include_usage` request. The policy requires streaming chat and
server-authoritative token counts because the first-content-chunk count and the
final output sequence length must use the same completion-token unit.

The first content-bearing response is the response whose arrival defines TTFT.
When that response carries cumulative `usage.completion_tokens`, upstream retains
the value as `first_content_chunk_tokens`. ITL then divides the decode window by
`output_sequence_length - first_content_chunk_tokens`, rather than always
subtracting one. This corrects per-user output throughput when a server bundles
multiple generated tokens in its first streamed content chunk. Missing, zero,
negative, or `>= OSL` first-chunk counts fall back to the legacy `OSL - 1`
divisor; an inconsistent reported value warns only once.

The upstream mock server can bundle the first N output tokens and emit cumulative
usage on every reasoning/output chunk. Unit tests cover option propagation and
validation, request body preservation/defaulting, parser gating and reasoning
units, corrected/fallback ITL formulas, and a component integration run against
that mock behavior.

## Native applicability and gaps

The native runtime already requests `include_usage` for streaming chat when
`use_server_token_count` is enabled, reconciles final usage, preserves meaningful
content-chunk timestamps, and derives OSL/ITL/TPS-user. It does not retain the
usage value attached to the first meaningful content chunk and has no authored
per-chunk policy.

The complete native gap is:

- CLI, Config-v2 YAML, typed config, endpoint-profile, protocol, and prepared
  endpoint propagation for `per_chunk_usage`, including camel-case aliases where
  those authoring surfaces already accept them.
- fail-closed validation that the option is used only with `chat`, `streaming`,
  and `use_server_token_count`, for both the default endpoint and named profiles;
- request construction that defaults `include_usage` and
  `continuous_usage_stats` independently without overwriting authored
  `stream_options` keys or explicit values;
- capture of cumulative `completion_tokens` on exactly the first meaningful
  content chunk, gated by the authored option, while terminal usage continues to
  use the latest non-empty values;
- retention through the transport-neutral `ObservedUsage`, native metrics
  observer, `RecordIngest`, and cellular/folded metric paths;
- corrected ITL and dependent TPS/user formulas in the main metrics plane and
  adaptive window sampler, with legacy fallback for absent or inconsistent
  values;
- a deterministic native mock response capable of first-chunk bundling and
  cumulative per-chunk usage, plus production-binary integration coverage.

The option is intentionally not generalized to completions, Responses,
WebSocket, gRPC, dry-run, or non-streaming endpoints because upstream injects the
vendor extension only for streaming OpenAI-compatible chat.
