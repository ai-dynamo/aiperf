# Commit 060 — `c2889280a6`

## Upstream intent

Upstream makes file-backed `random_pool` batching a four-modality contract.
Text, image, audio, and video each have an optional non-negative batch size,
defaulting to one. A zero disables that modality. If any modality present in the
source has a non-unit size, the loader flattens the unnamed source and samples
each present modality independently with replacement; unit sizes on the other
present modalities still contribute content.

Flattening intentionally breaks cross-modal associations, so upstream refuses
sources whose identity would be lost: directory or inline multi-pool inputs,
named content groups, and image UUID/cache metadata. It also refuses a turn when
all present modalities are disabled. A non-unit size for a modality absent from
the source is a no-op and does not force flattening.

The configuration change projects all four values through CLI and YAML, keeps
explicit CLI values above YAML, preserves authored zeroes, accepts the existing
camel-case YAML aliases, rejects these controls on public and non-`random_pool`
file datasets, and rejects non-unit batching for directory inputs before
services start. Synthetic YAML remains valid because its batching controls are
owned by the synthetic dataset path.

## Native semantic gap

The native `RandomPoolComposer` already implements independent-with-replacement
sampling and zero suppression for all four modality option keys. The complete
behavior is not exposed or guarded:

- `Inputs` and both Config-v2 projection paths carry only the image batch size;
  text, audio, and video CLI/YAML values cannot reach the composer.
- File and public dataset resolution do not reject random-pool-only sizing on
  the wrong dataset kind or format, and directory inputs accept lossy batching.
- The composer selects flattened mode from the four configured numbers alone.
  Thus `image_batch_size: 0` incorrectly flattens a named text-only source even
  though no image is present.
- Flattened mode silently discards pool/group identity and image UUID metadata,
  and it can emit an empty turn when every present modality is disabled.

The native YAML shape already has modality sections
(`dataset.prompts/images/audio/video.batchSize`), and a recently merged partial
fix correctly maps `dataset.images.batchSize`. This port extends that native
shape and preserves the existing fix rather than importing upstream's Python
schema or replacing the native loader.

## Native design decision

Keep the existing four option keys at the loader boundary. Add the three missing
authored fields beside the existing image field in `Inputs`, because this is the
smallest change and preserves the partial image fix. CLI-only and YAML loading
populate those fields from their native modality controls; explicit CLI values
overlay only their matching YAML value. Dataset resolution owns kind, format,
and directory validation, then serializes the values into file options.

The composer determines whether batching is requested only from modalities that
actually contain content. Before flattening it rejects every identity-bearing
source and validates that at least one content group can be emitted. Associated
unit-mode behavior is unchanged.
