# Origin #16 closure: profiling grace default

Upstream commit `5ad08166a1` preserves the default 30-second profiling grace
when `--benchmark-duration` is supplied without an explicit
`--benchmark-grace-period`. It covers both generated profiling phases and
CLI-overlaid profiling phases from a config file; explicit positive and zero
values remain authoritative. The upstream change has unit tests only and no
separate integration or end-to-end test.

Native Config v2 now implements the same rule. Generated profiling resolution
derives a 30-second grace only when duration is present and the grace input is
absent. The phase overlay path applies the same default only when the target
profiling phase has no authored grace, preserving YAML values and explicit CLI
values.

Native coverage:

- `rust/cli/src/load.rs` tests generated duration-only, explicit-zero, and
  explicit-positive profiling configurations.
- `rust/runtime/src/config/phase_validate.rs` tests duration overlays adding
  the default and preserving authored grace, covering the config-file overlay
  path.

No additional integration/E2E port is needed: the behavior is configuration
resolution and the external upstream tests are unit-level.

Disposition: applicable; native implementation and tests added. Exact merge
performed for campaign ancestry.
