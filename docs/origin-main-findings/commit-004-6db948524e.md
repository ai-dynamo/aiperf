# Commit 004 — `6db948524e`

Upstream subject: `fix: uncaught valueerror in sagemaker loader (#1199)`.

## Scope decision

**Already covered by the native Rust loader.** No Rust product change, design
specification, or Sol implementation plan is required for this commit.

The upstream Python change catches `TypeError` and `ValueError` from
`datetime.fromisoformat()` while parsing a SageMaker Data Capture record's
`eventMetadata.inferenceTime`, then translates that failure to
`DatasetLoaderError` with the capture event id.

Native `SageMakerDataCaptureDatasetLoader::load` calls `parse_capture` for
every record in `rust/runtime/src/dataset/loader/trace.rs:919-930`.
`parse_capture` requires `inferenceTime` to be a string
(`trace.rs:1053-1056`) and maps every `parse_iso8601_ms` failure into
`DatasetError::Validation` at `trace.rs:1057-1059`, retaining the record
origin in the error. Missing timestamps remain a missing-field validation;
present non-string values are reported as invalid timestamps, so neither case
can escape as an untyped parse failure.

## Verification implication

The closest native behavior test is
`rust/runtime/src/dataset/loader/trace.rs:1577-1599`, which currently proves
successful SageMaker capture loading. A future parity-hardening test could feed
`"inferenceTime": "not-a-timestamp"` to the same loader and assert a
`DatasetError::Validation` containing `invalid inferenceTime`; it is test-only
coverage, not a missing product behavior. The end-to-end SageMaker capture
route is separately exercised by
`rust/e2e-tests/tests/test_sagemaker_data_capture.rs`.

The focused native regression `sagemaker_rejects_malformed_inference_time_with_validation_error`
now covers a non-string timestamp and asserts the `DatasetError::Validation`
diagnostic includes the event origin and `invalid inferenceTime`.
