# Origin commit 9be59a9636: AMD telemetry integration tests

## Finding and test audit

The upstream commit adds five AMD-SMI integration scenarios and vendor-isolation
checks to `tests/integration/test_gpu_telemetry.py`. They cover mocked AMD
collection, JSONL export and custom prefixes, telemetry disablement, derived
energy-efficiency relationships, filtering of the `N/A` memory-activity field,
and per-GPU AMD/NVIDIA metric namespaces. It also changes the Python analyzer's
default missing-telemetry warning to debug when DCGM was only implicitly probed,
and makes the fake AMD-SMI package part of the Python install target. There are
no upstream unit or E2E files in this commit beyond the integration test file.

The native Rust runtime already implements AMD-SMI through the runtime-loaded
`libamd_smi.so` worker and has fixture coverage for AMD lifecycle, normalized
metrics, JSONL identity, summaries, and shutdown. The native CLI accepts the
`amdsmi` collector and rejects incompatible URL options. The Python fake-
`amdsmi` process harness cannot be directly ported because native execution
requires the host AMD SMI shared library; adding a second fake ABI would change
the production seam. Existing native fixture and CLI coverage is the applicable
equivalent, while the vendor-isolation assertions are enforced by platform-
tagged metric normalization in the runtime.
